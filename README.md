# Хранение данных в базе данных SQLite с помощью ORM ROOM
Если данные приложения подвержены изменениям, имеют сложные взаимосвязи, но главное их объемы значительны, то следует реализовывать хранение в базе данных. Реляционная СУБД SQLite уже интегрирована в мобильную операционную систему и для ее использования не требуется интеграция вспомогательных библиотек. Но для упрощения работы с базой данных можно подключить рекомендованную разработчиком ORM-библиотеку (Object-Relational Mapping) ROOM, которая возьмет на себя ряд общих действий - осуществление запросов к базе данных, преобразования данных к объектам предметной области и пр.

## Подключение зависимостей
Для подключения ORM ROOM необходимо не только добавить зависимости в файл build.gradle (уровня модуля):
```
dependencies {
    implementation("androidx.room:room-runtime:2.8.4")
    implementation("androidx.room:room-ktx:2.8.4")
}
```

Но и подключить актуальный KSP-плагин, который будет отвечать за преобразование аннотаций (@Entity, @Dao, @Database) в классы для работы с базой данных. Для этого в файл build.gradle (уровня модуля) добавляем плагин и зависимость:
```
plugins {
    alias("com.google.devtools.ksp:2.3.3")   // add KSP (Kotlin Symbol Processing)
}
dependencies {
    ksp("androidx.room:room-compiler:2.8.4")
}
```

А также указание на плагин в файл build.gradle (уровня проекта):
```
plugins {
    alias("com.google.devtools.ksp:2.3.3") apply false
}
```

## Описание сущностей базы данных
Сущности базы данных транслируются в data-объект, который обязан иметь аннотацию @Entity и один из атрибутов с аннотацией @PrimaryKey, с публичными полями (или публичными геттерами для доступа к полям). Обычно ROOM может транслировать "созвучные" имена столбцов базы данных и ваших атрибутов, но через аннотацию @ColumnInfo (для столбцов) или внутри @Entity (для таблицы в целом) можно задать явные значения:
```
@Entity (tableName = "jokes")
data class Joke (
    @PrimaryKey val id: Int,
    val isSingle: Boolean,
    val setup: String,
    val delivery: String?
    ) 
```

В качестве типов данных атрибутов используются либо базовые типы данных, либо иные @Entity-сущности (что позволяет моделировать предметную область со сложными отношениями).

## Создание DAO для сущностей
DAO-интерфейсы (Data Access Object) в данном случае описывают все возможные обращения к определенной таблице. Его необходимо пометить аннотацией @Dao.

Многие запросы легко генерируется через ROOM (создание - @Insert, удаление - @Delete, обновление - @Update). Более сложных запросы осуществляются через @Query с уточнением SQL-запроса, в который также можно также передавать параметры (место инъекции в SQL-запросе обозначается двоеточием):
```
@Dao
interface JokesDAO {
    @Query("SELECT * FROM jokes")
    fun getAllUsers(): Flow<List<Joke>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertAll(joke: Joke)

    @Delete
    suspend fun deleteAll(jokes: List<Joke>)
}
```
Отличительной особенностью от языка на Java является вкладывание механизмов для асинхронного взаимодействия - изменений внутри корутин и использование асинхронного потока считанных из базы данных во Flow.kt

## Создание объекта соединения с базой данных
Когда сущности были созданы, dao-интерфейсы объявлены необходимо создать абстрактный класс, наследуемый от RoomDatabase, который будет описывать структуру базы данных и текущую версию (внутри аннотации @Database), а также возвращать ссылки на сгенерированные реализации DAO-классов для указанных сущностей:
```
@Database(entities = [Joke::class], version = 1)
abstract class MobileDatabase : RoomDatabase()
{
    abstract fun jokesDAO() : JokesDAO    
}
```

Также можно добавить классы, содержащие логику @TypeConverter для преобразования специфических типов в базе данных к типам определенным в cущностях (например, если дата хранится текстом, а не объектом timestampt)

## Открытие соединения 
Для открытия соединения потребуется контекст (деятельности, фрагмента, сервиса или самого приложения). Один из вариантов описания открытия соединения - это создание объекта-компаньона внутри класса-наследника от RoomDatabase: 
```
abstract class MobileDatabase : RoomDatabase(){
   companion object {
        val db = Room.databaseBuilder(
            MobileApplication.mobileApplicationContext(),
            MobileDatabase::class.java, "DB"
        ).build()
    }
}
```

На открытом соединении можно получать экземпляры DAO-классов и уже с их помощью обращаться и исполнять те или иные запросы:
```
MobileDatabase.db.jokesDAO().getAllUsers()
```
